# Architecture

The sandboxed renderer receives a narrow, validated Electron preload API. It has no Node integration. IPC handlers accept only the application's own webContents; window creation and top-level renderer navigation are blocked. React renders real controller snapshots, never simulated product measurements.

`Controller` owns one absolute cycle deadline, a circular keyword index, cancellable worker tasks, a fresh-pool allocator and per-run challenge latches. Browser state changes do not adjust the deadline. API requests have cancellation, timeouts, response limits and bounded retry batches. Every successful initialization obtains a separate response; insufficient unique proxies leave logical session tiles waiting rather than opening direct connections. The initialization fan-out is eight, while all configured contexts can become active; memory thresholds can defer a requested context without changing the configured logical count.

At rotation the controller cancels workers, closes contexts, joins outstanding work, releases allocations, discards the old pool, completes the persistent cycle record, advances the keyword, and fetches again. The next deadline begins only after initialization. Completed ranking writes use on-disk SQLite and survive browser cleanup. Pause uses the same disposal mechanism while retaining remaining duration and keyword.

`ChromiumDriver` owns one Chromium browser process tree and independent incognito contexts. Proxy, cookies, storage, viewport and state are per context. Proxy replacement creates a new context. Generation checks close launches that finish after Stop. Each context owns listeners, cancellation and idempotent disposal; ordinary errors are isolated. Only authorized controlled tests may consume the bounded replacement-proxy recovery budget. Access challenges suspend the affected session ID until a new explicit Start.

The SERP inspector combines semantic headings, structural roots, fallback containers, URL normalization, visibility and loading checks. It excludes recognized sponsored blocks and counts observed organic results cumulatively across pages rather than assuming ten per page. Organic positions differ from element positions. The element ordinal counts the recognized DOM result candidates, including recognized sponsored blocks; it is not a verified absolute position among every possible Google widget. Unsupported or partially interpreted pages produce inconclusive observations. Google consent/custom result structures can require a later selector adaptation; fixtures cannot establish current live Google compatibility.

Keep Alive uses real mouse wheel input, pointer movement and Playwright link clicks. Origins and path prefixes define the authorized navigation scope. Chromium CDP intercepts main-frame requests, including server redirect destinations, before navigation outside that scope. Eligible internal links must remain in the current origin and pass conservative action/download checks. A visited set prevents accidental article loops. No eligible link causes further scroll checks while the cycle remains active; the configured navigation-depth limit causes waiting until rotation.

The main process samples its process descendants. Linux reports aggregate RSS and, when all processes permit reading it, proportional set size (PSS) to account for shared memory. Windows reports working sets and cumulative kernel/user CPU from the process tree. CPU is aggregate core usage: 100% represents one fully used logical core, so values may exceed 100%. System RAM and process memory are separate measurements. The central memory guard uses the tighter OS/cgroup memory limit where available.

Thumbnails are collected at a low frequency and dashboard emission is capped at four per second. The selected session preview is on demand. SQLite queries and UI history are bounded; exports read all rankings. Live processes and runtime authentication must restart after a cloud snapshot restore.
